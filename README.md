# 📚 ebook-promotions

一個**給懶人用的電子書平台活動彙整頁**。

👉 線上頁面：  
https://sapling1107.github.io/ebook-promotions/

---

## 這是什麼？

這個頁面存在的唯一目的就是：

> **我不想每天打開一堆電子書平台，一個一個看活動。**

所以提出了一堆任性又零碎的需求，  
然後交給 Ashel（ChatGPT）想辦法把它們湊成一個真的能跑的東西。

結果就變成了你現在看到的這個頁面。

它不是比價工具，也不是推薦系統，  
只是單純的 **「活動集中清單」**。

---

## 這個頁面會做什麼？

- 彙整各平台目前可見的活動標題或入口  
- 每日自動更新  
- 標示「🆕」代表與前一天相比新出現的活動  
- 點擊後回到各平台官方活動頁  
- 針對不同平台採用不同策略：
  - 可穩定抓取的，顯示活動標題
  - 不穩定或不適合硬抓的，保留官方入口

---

## 這個頁面不會做什麼？

- ❌ 不幫你算折扣哪個最划算  
- ❌ 不推薦你該買哪本書  
- ❌ 不保證活動內容、優惠條件或有效期限一定準確  
- ❌ 不會為了單一平台無限對抗防機器人機制  

如果你需要精確折扣或購買建議，  
請直接以各平台官方資訊為準。

---

## 目前收錄的平台

### 自動擷取活動

- BookWalker  
  - 部分擷取  
  - 只整理活動頁中可辨識的活動卡片  
  - 排除明確常駐入口、歷史報告與已確認過期活動
- Pubu  
  - 完整擷取目前活動頁回應中的可見活動卡片  
  - 不代表爬取 Pubu 全站或其他分頁  
  - Pubu 每日 99 元專區是補充入口，不算活動卡片
- Kobo  
  - 部分擷取  
  - 只擷取指定「本月出版精選」頁面中的明確活動標題連結  
  - 不是 Kobo 全站活動清單

### 入口模式

- Readmoo  
  - 不 fetch、不 parse，不再嘗試擷取活動卡片  
  - 保留官方活動入口  
  - 另提供「每日優惠」補充入口
- HyRead  
  - 不 fetch、不 parse  
  - 保留官方活動入口
- 博客來  
  - 不 fetch、不 parse  
  - 保留指定官方活動入口

---

## 為什麼有些平台是入口模式？

因為不是每個平台都適合同一種抓取方式。

有些平台頁面結構穩定，適合直接整理活動標題；  
有些平台會遇到 403、400、JavaScript 驗證、或頁面資訊流混雜等問題。  

這種情況下，與其硬抓出一堆不穩定或難看的結果，  
我更傾向：

> **保留官方入口，讓頁面至少穩定、能用、也不至於誤導。**

所以像 Readmoo、HyRead、博客來，目前就維持入口模式，不執行抓取或解析。

---

## 那 Kobo 為什麼只做部分擷取？

Kobo 目前只整理指定「本月出版精選」頁面中明確的活動標題連結：

- 不掃描書卡
- 不整理價格、作者或購物車內容
- 不代表 Kobo 全站所有活動

也就是說，Kobo 是部分擷取模式，不是完整活動清單。  
這樣比較符合頁面結構，也比較不容易抓到書名、價格、購物車按鈕之類的雜訊。

如果一般請求拿不到活動資料，才會使用 Playwright 作為 Kobo 專用 fallback。

## 技術說明（非常簡略）

- 由 Ashel 協助撰寫與調整抓取邏輯  
- 使用 GitHub Actions 定期執行  
- 產生靜態 JSON 與 HTML  
- 透過 GitHub Pages 發佈  
- 依平台狀況混合使用：
  - `requests`
  - `BeautifulSoup`
  - Playwright（只作為 Kobo 的 fallback）

Readmoo、HyRead、博客來採入口模式，不執行抓取或解析。

本專案沒有後端、沒有資料庫，也沒有帳號系統。

---

## 注意事項（請務必看）

> 本頁僅彙整各平台目前可見的活動標題，或保留官方活動入口，用於快速瀏覽與比對是否有新增活動。  
> 活動內容、折扣條件、實際有效期限與最終頁面呈現，請以各平台官方頁面公告為準。

另外：

- 「🆕」代表與前一天相比新出現的活動  
- 不代表它一定是整個平台第一次出現的優惠類型  
- 入口模式平台不一定會有可比較的活動標題清單
